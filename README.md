# 归拾

把自己写下的东西收在一处的本地个人信息管家：随手记、手动归类、加标签、写摘要、抽待办、按时间回顾。

没有账号，没有服务器，没有任何外部请求。数据只存在你自己的浏览器里，随时可以导出带走。

在线试用：<https://zzhe2868.github.io/guishi/>（同一份代码托管在 GitHub Pages，数据仍然只写在你的浏览器里）

## 特点

- **打开就能用**：一个 `index.html`，原生 ES 模块，没有构建步骤，也没有运行时依赖
- **数据在本地**：存在浏览器的 IndexedDB 里，不经过网络
- **能进能出**：一键导出 Markdown（给人看）或 JSON（可导回），也能从 JSON 恢复
- **桌面和手机都能用**：窄屏自动切成底部导航

## 功能

| 页面 | 能做什么 |
|---|---|
| **收件箱** | 一个输入框记下任何内容，落库前先选个分类；之后在详情里补标题、标签、摘要、要点 |
| **待办** | 直接添加，或从任意一条记录「设为待办」；优先级点击切换、截止日用日期选择器、标题点开就能改 |
| **回顾** | 选 7 / 30 / 90 天，看新增记录、活跃天数、待办完成情况、分类与标签分布、每天写了多少，并导出成 Markdown |

贯穿三个页面的还有：关键词检索（多个词空格分隔、AND 匹配、命中高亮）、分类与标签筛选、标签改名与合并、详情抽屉里的「相关记录」（按共同标签和正文重合度排序）。

## 快速开始

需要 Node 18+，只是为了起一个静态服务。

```bash
git clone https://github.com/zzhe2868/guishi.git
cd guishi
npm start
```

打开 <http://127.0.0.1:5173>。

不想用 Node 也可以，任何静态服务器都行：

```bash
python3 -m http.server 5173
```

> 不要直接双击 `index.html`。`file://` 协议下浏览器会拦掉 ES 模块，页面会是白的。

## 数据存在哪

IndexedDB，数据库名 `guishi`，两张表：`entries`（记录）和 `tasks`（待办）。

有几件事值得提前知道：

- **换浏览器、换设备、清站点数据，数据都不会跟过去** —— 先用「备份 → 导出 JSON」带走
- 无痕窗口关掉就没了
- `localhost:5173` 和 `localhost:8080` 算两个不同的站点，数据不互通
- 容量上限由浏览器分配（通常是几百 MB 量级），几千条文字记录远用不到

侧栏底部会显示当前存了多少条、占了多少空间。

  main.js             启动、路由、快捷键、备份菜单

## 键盘

| 键 | 作用 |
|---|---|
| `N` | 跳到输入框 |
| `Ctrl` / `⌘` + `K` | 聚焦搜索 |
| `Ctrl` / `⌘` + `Enter` | 保存当前记录 |
| `Enter` | 待办标题编辑后提交 |
| `Esc` | 关闭抽屉或弹窗 |

## 备份格式

「导出 JSON」得到的文件：

```json
{
  "app": "guishi",
  "version": 2,
  "exportedAt": "2026-11-13T10:00:00.000Z",
  "counts": { "entries": 12, "tasks": 3 },
  "entries": [
    {
      "id": "e-lq3k2a8f3b",
      "raw": "原始记录全文",
      "kind": "idea",
      "title": "标题",
      "summary": "摘要或 null",
      "tags": ["产品"],
      "key_points": ["要点一"],
      "created_at": "2026-11-13T09:12:00.000Z",
      "updated_at": "2026-11-13T09:12:00.000Z"
    }
  ],
  "tasks": [
    {
      "id": "t-lq3k2b1c9d",
      "entry_id": "e-lq3k2a8f3b",
      "title": "画原型第一版",
      "status": "todo",
      "priority": "high",
      "due_date": "2026-11-15",
      "created_at": "2026-11-13T09:20:00.000Z",
      "completed_at": null
    }
  ]
}
```

导入时会逐条校验：没有 `raw` 的记录、没有标题的待办会被跳过；`kind`、`priority`、`due_date` 不合法的会被纠正成默认值。同 `id` 的内容以文件里的版本为准，其余追加。

## 边界

- **没有账号系统**：这个浏览器就是唯一的边界，别人用你的电脑就能看到
- **没有加密**：内容以明文存在 IndexedDB 里，开发者工具就能读到
- **「相关记录」只做排序**：按共同标签和正文的二元词重合度算分，不理解语义，也读不出言外之意
- **「回顾」只有计数**：没有总结、没有建议，数字都能在列表里逐条对上

## 开发

```bash
npm start        # 本地预览 http://127.0.0.1:5173
npm run check    # 提交前自检
```

`check` 会拦住这几类问题：

- 语法错误
- 导入了不存在的导出名、引用了不存在的模块
- JS 里写了 `index.html` 中不存在的 id
- 页面引用了不存在的文件，或指向外部域名
- 路径、邮箱、令牌等不该进仓库的字符串
